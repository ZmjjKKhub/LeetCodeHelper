# 刷题 + 复盘系统 · 设计方案 v1

> 用途：本地单人工具，服务于「灵神题单」式的专题刷题法
> 交付方式：本文档作为 Claude Code 的输入，按 Phase 逐个实现

---

## 0. 设计约束（优先级最高，任何功能取舍都服从这一节）

| # | 约束 | 说明 |
|---|---|---|
| C1 | **录入摩擦 = 生死线** | A/B 类题记录 ≤ 20 秒（3 次点击内完成），C 类卡片 ≤ 3 分钟。任何需要打字超过 5 个字段的默认流程都要重新设计 |
| C2 | **单人本地，无需登录/权限/多租户** | 不要 auth、不要用户表、不要 RBAC。数据放本地 SQLite 文件 |
| C3 | **离线可用** | 不依赖任何外部 API 才能跑起来。LeetCode 数据抓取是可选增强，不是前置依赖 |
| C4 | **系统不知道 LeetCode 上发生了什么** | 用时、提交次数、是否 AC 全部手动录入。UI 必须为「快速手动录入」优化，不要设计成需要精确数据的报表系统 |
| C5 | **单进程启动** | `uv run app.py` 后浏览器打开 localhost 即可用。不要 docker-compose，不要独立前端 dev server |

---

## 1. 技术选型（已定，不要重新讨论）

| 层 | 选择 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI | 与既有技术栈一致 |
| 数据库 | SQLite + SQLModel（或 SQLAlchemy 2.0） | 单文件、零运维、易备份 |
| 前端 | Jinja2 服务端渲染 + HTMX + Alpine.js | 表单密集型场景，避免前后端两套状态；代码量约为 SPA 的 1/3 |
| 样式 | Tailwind CDN 或 Pico.css | 不引入构建链 |
| 迁移 | Alembic | 数据模型会随使用演进，必须有迁移 |
| 代码编辑器组件 | CodeMirror 6（CDN） | 模板编辑 / 默写测试需要 |

**明确不用**：React/Vue、Docker、Redis、Celery、任何独立前端构建。

## 2. 数据模型

### 2.1 静态数据

```
Problem                          # 题目（种子数据，基本不变）
  id                PK
  lc_id             int          # 力扣题号，如 76
  title             str
  url               str
  difficulty_score  int | None   # 灵神难度分
  section           str          # "§2.2" 越长越合法/求最短
  section_name      str
  is_starred        bool         # ⭐ 高频面试题
  is_premium        bool
  is_optional       bool         # 「选做/进阶」
  default_template  str | None   # 预期使用的模板 code，如 "C"
```

```
Template                         # 模板（活文档，会被反复修改）
  id                PK
  code              str UNIQUE   # "A".."F"
  name              str          # "不定长·求最短（越长越合法）"
  language          str          # "python"
  content           text         # 当前版本代码
  pitfalls          text         # 易错点
  trigger_signal    text         # 什么时候用它
  current_version   int
  updated_at        datetime
```

```
TemplateVersion                  # 模板历史版本（支持 diff 回看）
  id                PK
  template_id       FK
  version           int
  content           text
  change_note       str          # "补充了 del cnt[x] 的清理"
  triggered_by_problem_id  FK | None   # ★ 是哪道题让你改的模板
  created_at        datetime
```

> `triggered_by_problem_id` 是这个系统的核心设计，务必实现。它把「模板演进史」和「做题史」绑在一起。

### 2.2 计划

```
Plan
  id, name, start_date, days_per_week, minutes_per_day, status(active/archived)

PlanDay
  id, plan_id, day_index, planned_date, actual_date | None
  phase             str          # "阶段三 · 求最短+求个数"
  theme             text         # 当天要抽象出的东西
  status            enum         # pending / done / skipped / postponed

PlanItem                         # 某天安排的一道新题
  id, plan_day_id, problem_id, sort_order
  status            enum         # pending / done / deferred
```

### 2.3 做题与复盘

```
Attempt                          # 一次做题记录（新题或复习都用它）
  id                PK
  problem_id        FK
  attempt_date      date
  kind              enum         # new / review
  review_task_id    FK | None
  duration_sec      int
  submit_count      int
  first_try_ac      bool         # 是否一次通过
  mark              enum         # A / B / C
  used_template     str | None   # 实际用了哪个模板
  created_at
```

```
ReviewCard                       # 复盘卡片（C 类强制，B 类可选）
  id                PK
  problem_id        FK UNIQUE
  trigger_feature   text         # 题面里让你想到滑窗的那句话
  monotonicity      text         # 为什么 left 只需右移不需回退
  maintained_value  str          # sum / Counter / 不同元素个数 / 其他
  shrink_condition  text         # while ...
  count_timing      enum         # 入窗后 / 出窗循环内 / 出窗循环外
  blocker           text         # 我的卡点（一行）
  one_line_trigger  text         # ★ 看到「X」→ 用「Y」
  template_id       FK | None
  created_at, updated_at
```

```
ReviewTask                       # 复习队列
  id                PK
  problem_id        FK
  due_date          date
  round             int          # 第几轮（v1: 1..4 对应 D+1/3/7/14）
  status            enum         # pending / passed / failed / skipped
  attempt_id        FK | None
  created_at
```

```
DailyLog                         # 每日汇总（可由 Attempt 聚合，落库是为了查询快）
  date PK, new_count, review_count, first_ac_rate, c_ratio, total_minutes
```

```
DrillRecord                      # 模板默写 / 盲测记录
  id, drill_type(template_writing / blind_retest)
  target_id                      # template_id 或 problem_id
  passed bool, diff_result text, duration_sec, created_at
```

## 3. 核心业务规则（★ 最重要的一节，Claude Code 最容易做错的地方）

### R1 · 复习队列生成

做题打标后，自动生成 ReviewTask：

| 标记 | 生成的复习轮次 |
|---|---|
| 🟢 A | 不生成 |
| 🟡 B | D+3、D+14（2 轮） |
| 🔴 C | D+1、D+3、D+7、D+14（4 轮） |

生成时基于 `attempt_date` 计算 `due_date`。

### R2 · 复习结果处理（这条是系统的灵魂，不要简化）

复习时按限时判定（简单题 8 分钟 / 中等题 20 分钟，超时或未 AC = failed）：

```
if 复习 passed:
    标记本轮 passed，保留后续轮次不变

if 复习 failed:
    case round == 1 (D+1):
        整条队列重置 —— 删除该题所有 pending 轮次，
        以今天为基准重新生成 D+1/D+3/D+7/D+14
        并把 ReviewCard 标记为 needs_rewrite（卡片没写对）

    case round in (2, 3):
        本轮 failed，回退一轮 —— 在 (今天 + 上一轮间隔) 插入一次重做

    case round == 4 (D+14):
        触发「回炉」：
          1. 该题标记 relearn
          2. 把该题所属 section 下所有 mark==C 的题重新入队（D+1 起）
          3. 在首页给出提示：「§X.X 未掌握，建议重刷本小节」
```

### R3 · 每日任务组装

```
今日任务 = [到期的 ReviewTask（按 round 降序，越老的越先做）]
         + [今天 PlanDay 的 PlanItem]
```

UI 上复习队列必须排在新题**前面**，并且默认展开——脑子最清醒时做最难的事。

### R4 · 断更与顺延

- 某天 PlanDay 未完成 → **整体顺延**，后续所有 PlanDay 的 planned_date +1 天。不要标记为「失败」，不要产生补做积压。
- 连续 3 天未完成 → 首页红色提示：「建议回退到 [上一阶段名]，重刷该阶段的 C 类题」，并提供一键生成回退计划的按钮。
- 复习任务**不顺延**，逾期就是逾期，逾期任务在首页单独一栏高亮。

### R5 · 计划自适应建议（只建议，不自动改）

每周结束时计算，生成一条 `PlanSuggestion` 供用户确认：

| 条件 | 建议 |
|---|---|
| 周 C 类占比 > 40% | 下周新题量 −30%，腾出的时间给复习队列 |
| 周 C 类占比 < 10% 且模板默写连续 2 周满分 | 加入本阶段的「选做/进阶」题 |
| 周一次 AC 率 < 30% 且持续 3 天 | 提示当前阶段难度不匹配，建议回退 |
| 某 section 的 C 类题占该 section 题量 > 50% | 提示该小节需整体重刷 |

**必须是「生成建议卡片 + 用户点击接受/忽略」，绝不自动修改计划。** 自动改计划会让用户失去掌控感。

### R6 · 模板演进链路

- Attempt 记录 `used_template`
- 模板详情页反查：使用过该模板的题目列表（按 mark 分组，C 类高亮）
- 编辑模板时**必须**填 `change_note`，可选关联 `triggered_by_problem_id`
- 模板页展示版本时间线，任意两版可 diff（用 `difflib.unified_diff` 渲染）

## 4. 页面清单

### P1 · 今日（首页）

三块自上而下：

1. **逾期复习**（红色，如有）
2. **今日复习队列**：题目 + 第几轮 + 限时。每条一个「开始」按钮
3. **今日新题**：题目 + 难度分 + 所属小节 + 当天主题（theme）

**做题面板**（点击任一题展开，这是全系统最需要打磨的交互）：
```
[ 开始计时 ]  00:12:34  [ 暂停 ] [ 完成 ]
提交次数：  [-] 2 [+]
标记：      ( 🟢A )  ( 🟡B )  ( 🔴C )
用了模板：  [ A B C D E F 无 ]
                                    [ 保存 ]
```
点 🟢A 或 🟡B → 直接保存，流程结束（满足约束 C1 的 20 秒）
点 🔴C → 保存后跳转卡片填写页

### P2 · 复盘卡片

按 §3.1 的字段做表单。三个优化点：
- `maintained_value`、`count_timing` 用单选按钮而非文本框
- `one_line_trigger` 做成「看到 [____] → 用 [____]」两个输入框
- 提供「从同 section 的历史卡片复制」按钮，降低填写成本

### P3 · 计划

- 表格视图：Day / 日期 / 阶段 / 题目列表 / 状态
- 支持：整体顺延 N 天、某天增删题目、批量把某小节的题移到后面、手动插入题目
- 顶部展示进度条 + 当前阶段 + 距离下个验收题还有几天
- 展示待确认的 `PlanSuggestion` 卡片（R5）

### P4 · 模板库

- 6 个模板卡片列表 → 详情页
- 详情页：代码（CodeMirror 高亮）、易错点、触发信号、**使用该模板的题目反查列表**、版本时间线
- 编辑 → 强制填 change_note → 生成新 TemplateVersion
- 任意两版 diff

### P5 · 触发器库（面试前唯一要看的页面）

聚合所有 ReviewCard 的 `one_line_trigger`，按 section 分组展示成一张表：

| 看到什么特征 | 用什么方法 | 来源题 |
|---|---|---|

支持搜索、导出 Markdown。

### P6 · 检测

- **模板默写**：随机抽一个模板 → 空白 CodeMirror → 提交 → 与当前版本 diff → 记 DrillRecord
- **限时盲测**：从指定范围（本周 / 某 section / 全部 C 类）随机抽 N 题，倒计时，逐题记录通过与否
- **口述检查清单**：给定题目，展示 4 个必答问题（单调性 / 维护量 / 收缩与统计时机 / 为什么是 O(n)），自评打勾

### P7 · 统计

- 周报表：新题数 / 一次 AC 率 / C 类占比 / 总时长
- 按 section 的掌握度热力图（用 C 类占比着色）
- 一次 AC 率与 C 类占比的双折线趋势图
- 过关判定：C 类占比 < 15% 且模板默写连续 2 周满分 → 显示「本专题可结业」

## 5. 分阶段实施

| Phase | 内容 | 完成标志 |
|---|---|---|
| **1** | 数据模型 + Alembic 迁移 + 119 题种子数据（YAML → DB）+ P1 今日页的做题记录功能 | 能记录做题并打标，工具可用起来 |
| **2** | R1/R2 复习调度 + P2 复盘卡片 + 逾期展示 | 复习队列自动运转 |
| **3** | P4 模板库 + 版本 + diff + R6 双向反查 | 模板演进可追溯 |
| **4** | P3 计划视图 + R4 顺延 + R5 建议 + P7 统计 | 计划可调整 |
| **5** | P5 触发器库 + P6 检测（默写/盲测） | 完整闭环 |
| **6（可选）** | LeetCode GraphQL 抓取近期提交，自动预填提交次数与 AC 状态 | 消除大部分手动录入 |

**Phase 1 必须独立可用**，不要等到 Phase 5 才第一次跑起来。

## 7. 给 Claude Code 的执行提示

1. **先落 schema 再写业务**：第一步只做 models.py + 迁移 + seed 脚本，跑通后再往下。
2. **第 3 节的规则表逐条实现为独立函数并配单元测试**，尤其是 R2 的四个 case。这部分不要用 LLM 自由发挥的逻辑，要能被测试覆盖。
3. **所有日期计算用 `date` 不用 `datetime`**，避免时区问题。
4. **HTMX 局部刷新**：做题面板保存后只刷新那一行，不整页重载。
5. **不要引入后台任务队列**。每日汇总、复习到期判定全部在请求时惰性计算或用启动时的一次性检查。

## 8. 可选升级：把复习调度换成真正的算法

v1 的 D+1/D+3/D+7/D+14 是固定间隔，本质是一张查找表。如果想让这个项目有技术分量，v2 可以替换为 **SM-2** 或 **FSRS**：

- 每次复习记录「回忆质量」（可用 mark + 用时/限时的比值映射到 0–5）
- 维护每道题的 `easiness_factor`、`interval`、`repetition`
- 下次间隔由算法算出，而非查表
- 可加入「难度分」「所属 section 历史通过率」作为先验，做冷启动

这样复习调度就从 CRUD 变成了一个可调参、可评估的模型，也是面试里能展开讲的点：如何定义「记住了」、如何在数据稀疏时冷启动、如何评估调度策略优劣（比如用留存率曲线做 A/B）。

> 坦白说，本系统 v1 的技术含量基本是标准 CRUD，作为**自用工具**价值很高，但作为**简历项目**分量远不如你的 Coding Agent。上面这条升级路径是唯一能让它具备可讲深度的方向。
